Property Records: JSON and SQLite

Updated October 17, 2026. Plants, locations, purchases, cultivar profiles, mapped features, terrain, and water-harvesting records share one source.

Edit JSON, not the database. The repository's data/ collections are authoritative. A validated build generates local SQLite and the browser data used by these pages. The original workbooks are retained as source records, not a live spreadsheet connection.

Build and Query Locally

From the repository root, with Python 3.11+ and SQLite 3.37+ with JSON support:

python tools\property_data.py build
python tools\property_data.py check
python tools\property_data.py query "SELECT plant_id, metal_tag, site_ref, status FROM current_plantings WHERE cell = 'C17'"
python tools\property_data.py query --file database\queries\terrain_by_cell.sql
python tools\property_data.py query --file database\queries\water_budget.sql

The generated database is build\property.sqlite. Open it with a local SQLite viewer, or use the query command. Querying automatically rebuilds a stale database without publishing the website. Read-only SQL cannot modify records, attach another database, or load extensions.

Record a Location Without Duplicating It

i56-1 identifies one M-111 rootstock. orchard-r6-c3 identifies its spot at x 83, y 485, producing B10-E33-S35. A replacement plant can reuse the spot without reusing the dead plant's identity.

SiteRef, master-cell offsets, and GPS coordinates are calculated from lot feet. For an input code, use python tools\site_grid.py site-ref C17-E12-S18 to get x 112, y 818. See the grid guide for GPS conversion and its accuracy limits.

Most orchard entries are still planned assignments, not confirmation of planting. R6-C3 is confirmed planted; its exact planting date was not supplied. Outside-orchard locations display PENDING until assigned. An old vacated spot is not the tree's new location.

Updating and Publishing

  1. Edit the appropriate JSON collection. Retain individual IDs and history; use null for unknown dates or measurements.
  2. Run build, tests, and check. Invalid references, duplicate assignments, bad coordinates, and inconsistent mesh/climate inputs fail explicitly.
  3. Refresh affected printable PDFs and commit the JSON, generated browser data, and documentation.
  4. Push the changes. GitHub Pages publishes the static website; GitHub Actions validates the data and tests.

This is a public repository. Do not add private notes, credentials, or sensitive records. GitHub Pages cannot save database edits; the calculator's browser inputs are temporary what-if values, not persistent measurements.
